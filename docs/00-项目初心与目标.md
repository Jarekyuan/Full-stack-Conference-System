# 项目初心与目标（走偏时回来对照）

> **这份文档是什么**：记录"我为什么要做这个项目"和"我想把它做成什么样"。
> 它不描述怎么实现（那些在 01~05 文档里），它只回答"为什么"和"要什么"。
> **用法**：每完成一个里程碑，回来对着「第五章验收标尺」逐条核对——确认自己没有在忙碌中走偏。

## 一、我为什么要做这个项目（初心）

我是一名 **5 年前端开发者，正在向全栈转型**，目标求职市场在西安。我的技术栈已经明确调整为 **前端 React + 后端 Java + Spring Boot + MySQL + Redis**。

我手上有两类东西：

1. **两个真实的企业级旧项目**（我在之前公司接触过的生产代码）
2. **一套系统的面试学习笔记**（前端 4 份 + 后端 4 份 + Obsidian 里的学习文档系列，很多标注着"学过 ≠ 掌握"）

问题在于：**知识是散的，项目是旧的，两者没有发生化学反应**。所以我决定做这个新项目，用它把笔记里的技术点，在真实业务里**亲手用一遍**，沉淀成一个能拿得出手、能讲得深的作品。

**三重目标**（缺一不可，这是走偏时的第一道标尺）：

| 目标 | 含义 | 一句话检验 |
|------|------|-----------|
| ① 后端熟练化 | 用一套真实业务，把 Java 后端知识**串起来用一遍**：分层架构、MyBatis、Redis 缓存、分布式锁、状态机、定时任务、事件驱动、消息通知 | Java 是否从"学过"变成"做过"？ |
| ② 全栈闭环 | 前后端分离完整走一遍：接口设计 → 开发 → 联调 → **独立部署** | 是否补齐了"没独立部署过项目"的短板？ |
| ③ 面试主线项目 | 一个能让面试官听 15 分钟不打断的项目 | 有没有并发场景、技术选型、踩坑叙事、"我为什么这么设计"？ |

## 二、我从哪里来（三个来源）

## 三、我的核心想法（方法论）

### 3.1 总原则：提炼 ≠ 复刻

原系统是企业级生产代码（44 万行后端），**新项目只做减法，不做加法**：

- ✅ **保留**：能讲清楚、能深挖、闭环完整的核心流程
- 🔶 **简化**：保留骨架、砍掉分支复杂度
- ❌ **砍掉**：复杂度高但面试讲不出彩的部分（多租户、计费、第三方对接、IoT、日历同步、报表导出）

**筛选的唯一标尺**：一个模块，我能不能在面试里讲满 3 分钟？讲不满，就砍掉。

### 3.2 三条设计原则

1. **每个模块必须有一个可深挖的技术点**——拒绝纯 CRUD 堆砌。做 10 个 CRUD 模块，不如把 1 个"并发预约冲突"讲透。
2. **业务闭环完整**——能完整演示「预约 → 审批 → 进行中 → 结束 / 取消」全生命周期。
3. **复杂度可渐进**——分 P0 / P1 / P2 三档，每档都能独立运行、独立讲述。

## 四、我要把它做成什么样（目标状态）

### 4.1 技术栈（目标）

- **前端**：React + TypeScript（够用即可，不追求花哨）
- **后端**：Java 17 + Spring Boot 3 + Spring Cloud（Gateway / Nacos / OpenFeign）+ MyBatis（手写 XML）+ Redisson
- **中间件**：MySQL 8 + Redis + RabbitMQ
- **架构**：微服务 4 个（gateway / auth / meeting / notification）

### 4.2 业务范围（8 个模块）

认证与用户 · 会议室管理 · 预约核心 · 审批 · 通知 · 统计 · 周期会议 · 部署

### 4.3 必须能讲透的 9 个面试深挖点

1. **并发预约冲突**：锁粒度为什么是 `room + date`（不是 room，也不是精确时段）
2. **时间冲突检测**：半开区间 `[start, end)`、相邻不冲突、联合索引
3. **状态机**：6 状态（收敛原系统 12 状态）、迁移表集中管理、"为什么收敛"
4. **事件驱动**：`AFTER_COMMIT` 避免"通知发出但事务回滚"、同步 vs 异步
5. **审批时序**：待审批不占用时段 + 审批通过时复检冲突（两种策略的权衡）
6. **缓存**：穿透 / 击穿 / 雪崩 + single-flight 防击穿
7. **限流**：固定窗口 vs 滑动窗口（重构叙事）
8. **周期会议**：展开规则 → 逐场检测 → 整体失败 + 返回冲突清单
9. **延长会议**：上限的天然算法（下一场会议开始 − 缓冲）

### 4.4 面试讲述框架（最终交付形态）

- **1 分钟版**：一句话说清项目 + 两个核心工程问题
- **5 分钟版**：业务背景 → 技术选型理由 → 核心链路 → 一个深挖点
- **15 分钟版**：5 分钟版 + 三个深挖点 + **重构叙事**（老系统的问题 → 新项目怎么改）

## 五、验收标尺（项目结束时逐条核对）

### 结果层（9 个深挖点是否都能讲透）

- [ ] 延长会议（如实现）

- [ ] 全栈闭环的短板补上了（接口设计 → 开发 → 联调 → 部署）
