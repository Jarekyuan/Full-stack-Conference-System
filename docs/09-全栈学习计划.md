# 全栈学习计划（5 天 / 30 小时）

> 面向：**1-3 年全栈开发岗位**
> 背景：5 年前端 + 2-3 个月后端；短板集中在 Redis/锁/缓存、MQ/微服务/部署
> 目标：5 天 × 6 小时，把项目从“AI 写的”变成“我能讲、能改、能定位”的作品

> 每篇日教程约 800-1000 行：概念、核心代码逐段解释、边界与异常、举一反三、归纳/演绎记忆法、变体练习。

---

## 怎么用这份计划

1. **开一个学习分支**，不要直接在 `main` 上改代码：

   ```bash
   git switch -c study/fullstack-30h
   ```

2. **先跑起来**：预约/审批/通知零配置；会议纪要音频只走 COS，需在 `deploy/.env` 填 `COS_*`（ASR/AI 可先用 mock）：

   ```bash
   cd deploy
   cp .env.example .env
   docker compose up -d --build
   open http://localhost:8000
   ```

   也可以按 `README.md` 的本地开发模式启动 4 个 Java 进程 + Vite。

3. **每天固定节奏**：1h 概念 + 2h 代码走读 + 2h 手敲 + 1h 自测/复盘。
4. **每天结束**：做完 5 道自测，写 3 句话复盘；把答案/练习发给我，我按面试官标准追问。
5. **不要平均用力**：⭐ 必须掌握，🔍 理解即可，⚪ 了解/跳过。进阶细节不硬背。

## 笔记引用索引

教程用 `📘 笔记引用` 块引用你的笔记；类型说明：

> 引用类型：
> - 类型：A 项目直接对应
> - 类型：B 项目有差异
> - 类型：C 纯基础补充
> - 类型：D 了解/对比

- **A 项目直接对应**：笔记概念在项目有实现
- **B 项目有差异**：笔记用 Ribbon/Sentinel/Druid/PageHelper/pnpm/Next.js 等，项目用替代方案
- **C 纯基础补充**：Java/JS/HTTP 基础，不强行关联项目
- **D 了解/对比**：项目未使用，只讲概念

### 笔记差异速查

| 笔记里的写法 | 项目实际 | 面试怎么说 |
|--------------|----------|------------|
| Ribbon 负载均衡 | Spring Cloud LoadBalancer | “Ribbon 是旧方案，项目用 LoadBalancer；原理都是按实例列表选一个” |
| Sentinel 流控/熔断 | Resilience4j + Feign fallback | “项目用 Resilience4j 做熔断降级，限流是自研 ZSET+Lua” |
| Druid 连接池 | HikariCP | “连接池原理相通，项目没额外引 Druid” |
| PageHelper 分页 | 手写 `PageBounds` / `PageResult` | “分页 SQL 自己写，便于控制 count 和排序” |
| pnpm workspace | npm + package-lock | “项目用 npm；pnpm 的硬链接/严格依赖是加分项，不是项目经验” |
| Next.js / SSR / RSC | Vite + React 18 SPA | “项目是 SPA；SSR/RSC 我了解概念，但没有生产经验” |
| 完整 Spring Security 登录链 | 网关 JWT + `@PreAuthorize` | “认证在网关，服务内做方法级鉴权” |
| `BaseContext` | `UserContext` | 同一个 ThreadLocal 思路，类名不同 |
| HandlerInterceptor 鉴权 | Filter + 网关 `GlobalFilter` | “项目把鉴权放在网关和 Filter；拦截器/过滤器区别我能讲” |
| `@Async` / 自定义线程池 | 定时任务 + MQ | “异步主要靠 MQ 和定时任务，没有用 @Async” |
| Vue vs React | React 18 | 只作为对比题，不说项目用 Vue |

### 了解即可，不强行关联

- 《1.前端基础》HTML/CSS/浏览器安全/SQL 注入
- 《2.React知识点》SSR/Hydration/RSC/React 19
- 《3.Ts基础》条件类型/infer/工具类型
- 《4.前端工程化》Monorepo/微前端/Qiankun/Next.js

- 《11.Spring Boot》Bean 生命周期/循环依赖
- 《12...》主从复制/分库分表/Redis 高级
- 《13...》Sentinel/Ribbon/完整上线清单

## 取舍、风险与非目标

**取舍**

- 单库、无分布式事务：用本地事务 + AFTER_COMMIT 事件保证最终一致
- 通知只做站内信 + WebSocket，不做邮件/短信
- 不做词级时间戳：段级 + 标点切子句已经够用
- Compose 单机部署：面试演示足够，不是 K8s 项目

**风险与调整**

- 30 小时不够时：砍 `CalendarGrid` 几何细节、缓存/限流深挖
- 某天卡住超过 1 小时：先保留“能讲清思路”，跳过实现，Day 5 复盘补
- **保护 Day 3 锁和 Day 5 纪要 + 部署**，这两块是面试差异点

**非目标**

- 不从零重写整个项目
- 不逐行讲所有测试文件
- 不深挖 ECharts/Word 导出/日历几何的所有细节
- 不教 Java/Spring/React 入门
- 不把项目扩成 K8s/多租户/计费系统

## 成功标准

学完并完成检查点后，应能：

- 用 15 分钟讲完项目，并回答 20+ 个追问
- 手写 3 个核心片段：冲突检测、Redisson 锁、幂等
- 按业务在 1 分钟内定位前后端文件
- 说清“哪些是必须掌握、哪些是理解、哪些是了解”，不平均用力
