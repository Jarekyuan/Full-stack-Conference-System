# AGENT.md

本文件为 ai agent 在此代码仓库中工作时提供全局指导。

# 行为指南

1. 先思考，后编码
   不要想当然。不要掩饰困惑。要暴露权衡。
- 明确陈述你的假设。如果不确定，请提问。
- 如果存在多种解释，请列出它们——不要暗自挑选。
- 如果存在更简单的方法，请指出来。在有充分理由时提出反对意见。
- 如果某些内容不清楚，请停下来。指出令人困惑的地方。并提问。
2. 简单至上
   解决问题所需的最少代码。不要写推测性的代码。
- 不要为一次性使用的代码添加抽象层。
- 不要为不可能发生的场景编写错误处理。
- 如果你写了 200 行代码而 50 行就够了，请重写。
- 问问自己：“资深工程师会认为这过于复杂吗？” 如果是，请简化。
3. 精准修改
   只改动必须改的地方。只清理自己造成的混乱。
   在编辑现有代码时：
- 不要“改进”周围的代码、注释或格式。
- 不要重构没有问题的东西。
- 保持与现有风格一致，即使你个人偏好不同。
- 如果你注意到不相关的死代码，可以提出来——但不要删除它。
4. 目标驱动执行
   定义成功标准。循环验证，直到达标。
- “修复那个 bug” → “编写能复现该 bug 的测试，然后让测试通过”。
- “重构 X” → “确保重构前后测试都能通过”。
- 对于多步骤任务，陈述简要计划，按 [步骤] → 验证方式：[检查点]来执行。

# 项目规范

- 使用标准的团队代码规范
- 优先级: 安全 > 性能 > 可读性 > 简洁性

# 个人偏好

- 回复用中文，但代码、技术术语用英文
- 每个代码文件的头部需要简要说明这个文件的作用和核心功能（10行左右）
- 解释代码时简洁直接，不要啰嗦
- 使用组件化、模块化、工程化的思想
- 需要确认的操作（删除、清空数据等）先征求同意，不直接执行
- 修改超过 50 行的代码时，先展示改动计划
- 不确定的技术选型和解决方案，先列出方案对比而非直接选择
